# Переход тестировщиков со старой версии на текущую

Пользователи тестируют версию из последнего коммита (`96ee982`) и собирают обратную связь по правилам. Этот документ
фиксирует, что нельзя ломать и как перенести их данные.

## Что в старой версии, а чего нет

| | Старая версия (коммит 96ee982) | Текущая |
|---|---|---|
| Вход | один пароль администратора (`admin.json`), пока не задан — настройки открыты | учётные записи (`users.json`), первый запуск: `admin` / `admin` |
| Обратная связь | «не ошибка» → `exceptions.json` | отметки «верно / ложное / неточно», «не заметила», «неверно прочитано» → `feedback/reviews/`, журнал `feedback/actions.jsonl` |
| Панель | список групп | разделы, режим «По стандартам», описание каждой проверки, ОСТ4 ГО.070.014 / 015 |
| Проверок | 153 | 171 (добавлены O01–O18, действуют только при ссылке на ОСТ) |

## Что переносится без изменений

Скопируйте из папки старой версии в папку новой (рядом с `app.py` / exe):

* `config.json` — настройки, включение и важность правил (по кодам), свои правила, таблица замен;
* `exceptions.json` — «не ошибка» (по коду и тексту замечания);
* `work/` — сохранённые проверки и отчёты;
* `admin.json` — ключ сессий (пароль в нём не используется: вход теперь по `users.json`).

Формат этих файлов не менялся; новые поля (`custom_rules[].when_tt`, `dims[].thread_tol` в отчётах) необязательные.
Старые отчёты открываются как раньше; замечаний новых правил (O01–O18) в них нет, пока чертёж не проверен заново.

## Что нельзя менять, чтобы не потерять обратную связь

1. **Коды правил.** На них ссылаются `exceptions.json`, `config.json` (`rules`) и отметки. Код нельзя удалять, переименовывать
   и использовать повторно. Если правило не нужно — выключите его по умолчанию (`default=False` в `catalog.RULES`).
   Тест `test_rule_codes_backward_compatible` сверяет каталог с `tests/rule_codes_baseline.json` (коды, группа,
   включение по умолчанию, важность 153 правил старой версии) и падает при расхождении.
2. **Текст существующих замечаний.** «Не ошибка» для одного чертежа сопоставляется по коду **и точному тексту** замечания
   (`checking/exceptions.py: match`). Измените формулировку — скрытые замечания вернутся. Если формулировку менять необходимо,
   повысьте ревизию правила (п. 3) и предупредите пользователей, что скрытые замечания надо отметить снова.
3. **Ревизия правила.** В `checking/rule_docs.py` словарь `REV` — версия поведения правила (по умолчанию 1). Меняете то, что
   правило находит (условие, порог, диапазон), — увеличьте `REV["КОД"]`. Отметка хранит ревизию правила на момент отметки,
   «Настройки → Отметки тестеров» считает долю ложных только по текущей ревизии, а прежние показывает отдельно
   («до изменения»). Отметки старой версии, где ревизии нет, относятся к ревизии 1.
4. **Версия программы.** `checking/version.py: APP_VERSION` записывается в каждую отметку; меняйте при выпуске новой сборки
   для тестировщиков.

## Перенос «не ошибка» в отметки тестеров

Отметки «не ошибка» старой версии — это и есть их обратная связь («замечание ложное»). Чтобы они попали в сводку
«Отметки тестеров» (рядом с новыми отметками, ревизия 1, версия `legacy`), из папки программы:

```
python tools/import_exceptions.py [путь к exceptions.json]
```

`exceptions.json` не меняется и продолжает скрывать замечания. Повторный запуск дубли не создаёт.

## Порядок перехода одного тестировщика

1. Закрыть старую программу, сделать копию её папки.
2. Положить файлы из раздела «Что переносится» в папку новой версии.
3. Запустить новую версию, войти `admin` / `admin`, сразу сменить пароль («Профиль»), завести пользователей
   («Настройки» → «Пользователи»).
4. Выполнить `tools/import_exceptions.py`.
5. Проверить в «Настройки → Проверки по стандартам → Изменённые», что включение и важность правил остались прежними.
6. Прогнать контрольный пакет чертежей и сравнить с результатами старой версии: должны добавиться только замечания
   O-правил (при ссылке на ОСТ).
