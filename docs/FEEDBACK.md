# Как передать разработчику обратную связь по замечаниям

В программе три вида обратной связи; все они хранятся в папке `feedback` рядом с программой (рядом с exe — у exe-версии).

| Что | Где делается | Куда сохраняется |
|---|---|---|
| Отметки по замечаниям «верно / ложное / неточно» (с пояснением), «Программа не заметила», «Неверно прочитано» | в отчёте, у любого пользователя | `feedback/reviews/<проверка>.json` |
| **Комментарий администратора** к замечанию («комментарий» под замечанием): что на самом деле на чертеже, как должно быть | в отчёте, только администратор | туда же (тип `comment`) |
| Мнение эксперта по правилу и отметка «Утверждено» | Настройки → Проверки по стандартам → «i» у правила | `feedback/expert_notes.json`, `feedback/rule_reviews.json` |

## Передача
1. Администратор: **Настройки → Отметки тестеров → «Выгрузить для разработки (ZIP)»**. В ZIP: все отметки и комментарии, мнения экспертов,
   журнал действий, отчёты и сами чертежи (по ним можно воспроизвести замечание).
2. Файл ZIP положить в папку проекта (или передать путь к нему). Если exe запущен на этом же компьютере — достаточно
   указать папку `feedback` рядом с exe, ZIP не нужен.

## Что делает разработчик
```
python tools/review_digest.py выгрузка.zip                # сводка по правилам: ложные / неточные / комментарии
python tools/review_digest.py выгрузка.zip --code E01     # все замечания по правилу: чертёж, текст, пояснения, «как должно быть»
python tools/review_digest.py выгрузка.zip --comments     # только комментарии администраторов
python tools/expert_notes.py                              # мнения экспертов по правилам (из feedback/expert_notes.json)
```
Каждое замечание перепроверяется по тексту стандарта (`docs/norms/`) и по самому чертежу из ZIP; правило меняется с повышением
ревизии (`REV` в `checking/rule_docs.py`), на мнения отвечают через `tools/expert_notes.py reply` — ответ виден в панели.
Отметки привязаны к коду правила и его ревизии, поэтому переносятся между версиями (см. `docs/MIGRATION.md`).
