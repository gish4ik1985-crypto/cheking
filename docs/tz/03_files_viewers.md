# 03. Файлы, чертежи и 3D

## 1. Исходные условия (Решение принято, D-03)

- Сейчас в системе хранятся только PDF-версии чертежей.
- Перенос 3D-моделей с сервера почти готов.
- Нужно определить, как хранить, просматривать, проверять и версионировать 3D и чертежи вместе, и в какой мере взять методологические подходы.

Раздел содержит рекомендацию и варианты. Что именно выбрать, решаем после изучения текущей реализации (часть 09).

## 2. Принцип: исходник и вторичные представления

По методологии любой документ в процессе согласования должен иметь сформированное вторичное представление. Предлагается общий принцип:

| Что | Назначение | Пример |
|---|---|---|
| Исходный файл (источник) | Подлинник, неизменяемый после утверждения | `.m3d`, `.a3d`, `.cdw`, `.spw`, DOCX |
| Вторичное представление | Просмотр, согласование, печать, автопроверка | PDF чертежа, облегчённая 3D-модель |
| Нейтральный обменный формат | Передача партнёрам и архив | STEP AP242 для 3D, PDF/A для чертежей |

У каждой версии документа есть ровно один исходный файл и от нуля до нескольких вторичных представлений. Утверждение версии без обязательного вторичного представления невозможно (настройка по типу документа).

## 3. Что хранить на этапах

| Этап | Чертёж | 3D-модель |
|---|---|---|
| Сейчас | PDF (как вторичное и единственное) | Нет |
| Этап 1 | PDF плюс исходник `.cdw` при наличии | Исходник `.m3d` / `.a3d` и облегчённое представление для просмотра |
| Этап 2 | PDF/A как архивный экземпляр | STEP как нейтральный формат |

Проверки (существующий движок правил) при этом остаются работоспособными: по PDF, как сейчас, и дополнительно по данным 3D-модели и чертежа, когда исходник доступен (например проверка обозначения и штампа через считанные свойства).

## 4. Варианты хранения 3D

| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Хранить только исходник КОМПАС, просмотр через серверный конвертер | Минимум файлов, исходник единственный | Нужен конвертер, медленный первый просмотр |
| Б. Исходник плюс облегчённое представление (glTF/GLB) | Просмотр в браузере без КОМПАС, быстро | Нужен конвертер при загрузке, больше места |
| В. Исходник плюс STEP | Универсальный обмен | STEP тяжёлый, просмотр медленный |

Рекомендация: вариант Б для просмотра и вариант В для обмена на этапе 2. Исходник всегда хранится. Решение зависит от того, чем программисты умеют конвертировать, и должно быть подтверждено после изучения кода (Допущение).

## 5. Просмотр без САПР

- Просмотр PDF чертежа в браузере (с увеличением, поиском по тексту, переходом по листам).
- Просмотр 3D в браузере: вращение, сечение, измерения, дерево сборки с подсветкой.
- Наложение замечаний автопроверки на просмотр (если замечание привязано к листу, позиции или элементу).
- Сравнение двух версий: чертежи по листам с подсветкой различий, модели по составу и свойствам.

## 6. Взятие в работу и обратная запись

- Правки исходных файлов идут через «Взять в работу» и «Сохранить и вернуть» (часть 02). При возврате создаётся ревизия файла, хэш пересчитывается.
- Файлы неизменяемы. Каждый файл хранится по хэшу содержимого (дедупликация одинаковых файлов).
- Просмотрщик и автопроверка работают только с зафиксированной версией.
- После утверждения файл блокируется на запись на уровне хранилища.

## 7. Интеграция с КОМПАС-3D

По методологии интеграция с КОМПАС-3D реализуется набором правил преобразования данных между системой и файлами КОМПАС. Нужны следующие сценарии:

| Сценарий | Что делает |
|---|---|
| Получение информации из модели | Считывает состав и свойства модели в базу, создаёт или обновляет компоненты |
| Обновление состава модели | Приводит состав модели в соответствие с составом компонента в базе |
| Обмен основной надписи | Графы основной надписи документа обмениваются с атрибутами компонента и документа |
| Конфликтные данные | Правила обработки расхождений при получении (приоритет источника, запрос пользователю) |
| Материалы-заменители | Получение данных о материалах-заменителях детали |
| Связанные чертежи | Сохранение связанных чертежей при получении данных из модели |
| Синхронизация свойств | Соответствие свойств КОМПАС и атрибутов базы |
| Спецификация | Атрибуты записываются в примечания спецификации, выбор стиля групповой спецификации |

Правила преобразования хранятся как настройки, а не код. Для типов документов, кроме модели, настройка может задаваться отдельным файлом конфигурации. Состав и атрибуты не должны расходиться молча: расхождения попадают в отчёт.

## 8. Требования

| № | Требование |
|---|---|
| FIL-01 | Файл хранится неизменяемо, адресация по хэшу, дедупликация, контроль целостности. |
| FIL-02 | У версии документа один исходный файл и 0..N вторичных представлений. |
| FIL-03 | Утверждение версии без обязательного вторичного представления запрещено (настройка по типу документа). |
| FIL-04 | Просмотр PDF чертежей в браузере с постраничным переходом и поиском по тексту. |
| FIL-05 | Просмотр 3D-моделей в браузере, дерево сборки, сечения, измерения (этап 1, формат уточнить). |
| FIL-06 | Автоматическое получение вторичных представлений при загрузке исходника (фоновое задание, статус, повтор при ошибке). |
| FIL-07 | Сравнение версий: чертежи по листам, модели по составу и свойствам. |
| FIL-08 | Импорт данных из КОМПАС: состав, свойства, основная надпись, чертежи. Правила преобразования редактируются без кода. |
| FIL-09 | Обновление состава модели КОМПАС из базы с отчётом расхождений. |
| FIL-10 | Привязка замечаний автопроверки к листу и позиции в просмотрщике (по возможности). |
| FIL-11 | Запрет перезаписи утверждённых файлов на уровне хранилища, аудит доступа. |
| FIL-12 | Проверка формата и размера при загрузке, проверка на вирусы (настройка). |
