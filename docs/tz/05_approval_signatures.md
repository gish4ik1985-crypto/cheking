# 05. Согласование, подписи, нормоконтроль

## 1. Согласование и утверждение

Согласование выполняется по шаблонам процессов. Шаблон описывает стадии, исполнителей, условия переходов и автоматические проверки. Шаблоны управляются отдельно от кода и настраиваются администратором.

Шаблон процесса содержит:
- набор стадий; у каждой стадии характер работы (Разработал, Проверил, Согласовал, Начальник отдела, Н. контроль, Т. контроль, Представитель заказчика, Утвердил) и исполнители (роль, должность или конкретный пользователь);
- набор автоопераций и условий перехода между стадиями;
- состав обязательных подписей, определяемый типом согласуемого документа;
- длительность стадий и правила эскалации;
- права доступа: кто может запускать процесс по шаблону и насколько может его менять.

Типовые шаблоны: согласование и утверждение КД, ТД, изменений КД и ТД, заявок (на выдачу документов, на НСИ, на регистрацию документов), предварительное согласование, сбор и отработка замечаний, технологический контроль КД.

### Ход процесса

1. Инициатор создаёт рабочий процесс из шаблона. ИИ и все согласуемые версии прикрепляются автоматически.
2. Система проверяет условия запуска: заполнены обязательные атрибуты, сформировано вторичное представление, нет блокирующих замечаний автопроверки.
3. Согласующие получают задания во входящих. Они принимают задание в работу, знакомятся с документами, проверяют наличие и действительность подписей, подписывают или отклоняют с замечаниями.
4. Возможно промежуточное согласование: согласующий делегирует часть проверки другим специалистам. Результат собирается у ответственного за согласование.
5. Отклонённое возвращается разработчику с замечаниями в состоянии «Требует решения». Документы разблокируются для правок.
6. После подписи всех обязательных стадий документы автоматически переходят в «Утверждён». Условие перехода проверяется автооперацией.
7. Внешний согласующий (не пользователь системы) отмечается вручную с приложением подтверждения.

### Автооперации и проверки перехода

| Автооперация | Что проверяет или делает |
|---|---|
| Утверждение заявок | Переводит прикреплённые заявки в «Утверждён» или «Аннулирован», проверяет обязательные подписи |
| Проверка наличия подписей | Для каждого объекта проверяет наличие подписей с нужными ХР |
| Проверка схемы процесса | Проверяет, что в процессе есть стадии со всеми ХР, необходимыми для перевода в «Согласование» и «Утверждён» |
| Проверка заблокированных объектов | Проверяет, что документы в состоянии «Проектирование» не заблокированы другими |
| Подготовка к согласованию | Блокирует документ перед отправкой на согласование, исключая правки во время согласования |

## 2. Подписи

Поддерживаются три вида электронной подписи (63-ФЗ):
- простая;
- усиленная неквалифицированная;
- усиленная квалифицированная.

Для документов, выпускаемых без электронной подписи, используется бумажный информационно-удостоверяющий лист. Он создаётся отдельно на каждый электронный документ. В модели данных хранятся: обозначение документа, вид (электронный или бумажный), код документа, дата создания, количество листов, наименование «Наименование документа. Удостоверяющий лист».

Подписание версии фиксирует: кто, с каким ХР, каким видом подписи, когда, контрольную сумму файла. Изменение подписанной версии аннулирует подпись.

## 3. Нормоконтроль

Нормоконтролёр КД и ТД участвует как согласующий с ХР «Н. контроль» и «Т. контроль»:
- принимает задание в работу;
- проверяет наличие и действительность подписей, документы и данные;
- подписывает или возвращает на доработку с замечаниями.

Автоматическая проверка (движок правил проекта) выполняется перед отправкой на согласование и показывает нормоконтролёру результаты. Автопроверка не заменяет человека, она снимает рутину. Её результаты (замечания, уровень, статус) входят в карточку согласования.

| № | Требование |
|---|---|
| APR-01 | Шаблоны процессов согласования: стадии, ХР, исполнители, автооперации, условия. Управление без кода. |
| APR-02 | Создание процесса из шаблона с автоприкреплением ИИ и версий. |
| APR-03 | Проверка условий запуска: атрибуты, вторичное представление, блокирующие замечания. |
| APR-04 | Задания во входящих, принятие, отклонение с возвратом, промежуточное согласование. |
| APR-05 | Проверка подписей по ХР, определяемым типом документа. |
| APR-06 | Автоматический перевод в «Утверждён» после всех обязательных подписей. |
| APR-07 | Внешний согласующий с ручной фиксацией результата. |
| APR-08 | Виды ЭП: простая, неквалифицированная, квалифицированная. Подписание версии с контрольной суммой. |
| APR-09 | Информационно-удостоверяющий лист для документов без ЭП. |
| APR-10 | Блокировка документа на время согласования, разблокировка при возврате. |
| APR-11 | Роль нормоконтролёра. Результаты автопроверки видны в карточке согласования. |
| APR-12 | Сроки стадий, напоминания, эскалация. |
| APR-13 | Права на запуск процесса по шаблону и глубину его настройки задаются отдельно. |
| APR-14 | Контроль хода процесса для инициатора и подписчиков. |

## 4. Уведомления

| Событие | Кому |
|---|---|
| Назначено задание на согласование | Исполнителю стадии |
| Возврат на доработку | Разработчику и инициатору |
| Проведено изменение | Держателям копий и абонентам, подписчикам процесса |
| Отклонена регистрация изменений | Инициатору с причиной |
| Приближается срок стадии или ПИ | Исполнителю и инициатору |
| Снята чужая блокировка | Прежнему владельцу блокировки |

Каналы: внутри системы и по почте. Шаблоны уведомлений редактируются.

| № | Требование |
|---|---|
| NTF-01 | Уведомления по событиям таблицы, в системе и по почте. |
| NTF-02 | Шаблоны уведомлений и подписки настраиваются. |

## 5. Поиск, отчёты, печатные формы

- Поиск по обозначению, наименованию, атрибутам, состоянию, периоду, подразделению. Поиск документов по штрихкоду.
- Результаты поиска можно сохранять, фильтровать, выгружать.
- Отчёты: состав, «где используется», сравнение версий состава, комплектность, что взято в работу, состояние извещений, замечания автопроверки по проекту.
- Печатные формы документов: контрольный, рабочий (конструктора, технолога) и архивный экземпляры с разными штампами и подписями по ГОСТ 2.104, 2.106, 2.113, 2.503.
- Выгрузка в Excel и PDF.

| № | Требование |
|---|---|
| SRC-01 | Поиск по атрибутам, штрихкоду, содержимому текстовых документов. |
| SRC-02 | Сохранение и выгрузка результатов поиска. |
| SRC-03 | Отчёты из списка выше, выгрузка в Excel и PDF. |
| SRC-04 | Печатные формы: контрольный, рабочий и архивный экземпляры. |
