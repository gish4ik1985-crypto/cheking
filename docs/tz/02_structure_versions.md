# 02. Состав, версии, справочники

## 1. Электронная структура изделия (состав)

ЭСИ это структурная модель изделия: составные части на разных уровнях, иерархические отношения между ними и другие данные. Модуль хранит состав в собственной базе в виде компонентов и связей. КОМПАС-3D синхронизируется с ним по настраиваемым правилам (часть 03).

Виды ЭСИ (по ГОСТ Р 2.053): функциональная, конструктивная, производственно-технологическая, физическая, эксплуатационная. На первом этапе реализуются конструктивная и технологическая.

Конструктивная ЭСИ (ЭСК): основная (непосредственные составные части, без структуры потомков) и полная (с структурой потомков, кроме покупных изделий). Согласованию подлежит основная ЭСК.

Типы связей между компонентами:

| Связь | Смысл |
|---|---|
| Состоит из | Сборочная единица содержит составную часть (количество, позиция, раздел спецификации) |
| Изготавливается из | Деталь изготавливается из материала и сортамента |
| Документы | Привязка документов к компоненту |
| Исполнение | Связь между исполнениями изделия (ГОСТ 2.113) |
| Замена | Группы и варианты замены |

Связи ведут на компонент (по идентификатору и обозначению), а не на конкретную версию. Состав на дату строится по периодам действия версий (часть 04, влияние изменений).

Исполнения и варианты. Ряд взаимозаменяемых изделий с общими конструктивными признаками описывается групповыми или базовыми документами (ГОСТ 2.113). Постоянные данные исполнений хранятся в общем документе, переменные в таблице исполнений. Многовариантная ЭСИ допускает правила вхождения элементов в состав при выполнении условий. На первом этапе реализуется связь «Исполнение» и групповая спецификация, вариантные правила (условия вхождения) оставляем на этап 3.

### Требования

| № | Требование |
|---|---|
| STR-01 | Создание, редактирование и просмотр состава компонента: позиции, количество, разделы спецификации. |
| STR-02 | Хранение связей по компоненту, не по версии. Построение состава на дату. |
| STR-03 | Связи «Состоит из», «Изготавливается из», «Документы», «Исполнение», «Замена». |
| STR-04 | Построение перечня «где используется» на всех уровнях вверх с учётом даты. |
| STR-05 | Основная и полная ЭСК, переключение режима просмотра. |
| STR-06 | Групповые и базовые документы, исполнения изделия с постоянной и переменной частью. |
| STR-07 | Сверка состава с внешним источником (Excel, 1С): отчёт расхождений. Использует существующую сверку. |
| STR-08 | Контроль цикличности: компонент не может входить сам в себя прямо или косвенно. |

## 2. Нумерация

- Обозначение формируется автоматически из префикса родителя и значения нумератора, например `[Префикс]-[N]`. Нумератор настраивается: свой на проект, подразделение или тип.
- Уникальность обозначения контролируется в пределах базы. Запрет дублирования.
- Для стандартных и прочих изделий действуют правила записи по ГОСТ Р 2.106: наименование и обозначение по стандарту или документу на поставку. Для нормализованных изделий допускается децимальное обозначение, которое пишут в графу «Обозначение», условное записывают в графу «Наименование».
- Обозначение изделия и документов формируется по ГОСТ Р 2.201. Автогенерация для кода документа (СБ, ВП, РЭ и т.д.) берётся из справочника типов.
- Смена обозначения существующего компонента запрещена. При нарушении взаимозаменяемости создаётся новый компонент (часть 04).

| № | Требование |
|---|---|
| NUM-01 | Нумераторы с префиксами, настройка по проекту, типу, подразделению. |
| NUM-02 | Автоформирование обозначения при создании, с возможностью ручного ввода для стандартных и покупных изделий. |
| NUM-03 | Проверка уникальности обозначения, запрет изменения обозначения созданного компонента. |

## 3. Атрибуты и справочники

Каждый объект имеет карточку атрибутов. Для каждого атрибута задаются: тип значения, обязательность, источник (ручной ввод, автоматически, из файла), ключевой ли, виден ли пользователю. Системные скрытые атрибуты (например префикс проекта) наследуются дочерними объектами.

Справочники:
- **Материалы.** Наименование, обозначение по ГОСТ, плотность, группа, заменители. Привязываются к детали связью «Изготавливается из».
- **Сортамент.** Профиль, размеры, ГОСТ на сортамент. Привязывается к детали вместе с материалом (например «Балка 20Б1 ГОСТ 26020»).
- **Стандартные и покупные изделия.** Каталог с условным обозначением.
- **Организации и подразделения**, держатели подлинников.
- **Типы документов** (раздел 5).

| № | Требование |
|---|---|
| ATT-01 | Настраиваемые атрибуты по типу объекта и документа без изменения кода. |
| ATT-02 | Справочники материалов и сортамента с привязкой к детали. Значки по части 08. |
| ATT-03 | Каталог стандартных и покупных изделий. |
| ATT-04 | Обмен атрибутов с графами основной надписи и свойствами КОМПАС (часть 03). |

## 4. Версии и параллельная работа

Нужны три разных механизма: версионирование, блокировка и варианты. Они решают разные задачи, поэтому разделены (Решение принято, D-02).

### 4.1 Версии

- Версия неизменяема после утверждения. Любая правка создаёт новую версию (часть 04).
- Нумерация: основные версии 1.0, 2.0, …; временные по ПИ 1.1, 1.2, …
- Состояния версий по части 01. Старые версии не удаляются, хранятся до конца срока хранения.

### 4.2 Взятие в работу (блокировка)

- Редактирование документа в состоянии «Проектирование» возможно только после «Взять в работу». Блокировка выдаётся одному пользователю, остальным доступен просмотр последней сохранённой версии.
- Блокировка имеет владельца, время взятия и срок. Администратор может снять чужую блокировку с записью в журнал. Автоснятие по тайм-ауту настраивается (по умолчанию выкл.).
- Возврат «Сохранить и вернуть» создаёт промежуточную ревизию и снимает блокировку. «Отменить взятие» откатывает к последней сохранённой.
- На время согласования документ блокируется целиком (ему присваивается признак «заморожен»). При возврате на доработку автор может разблокировать документ для правок.
- Проверка заблокированных объектов: отчёт «что сейчас взято в работу и кем» по проекту (для документов в состоянии «Проектирование»).

### 4.3 Варианты в состоянии «Проектирование»

- В состоянии «Проектирование» допускается несколько версий одного документа, которые являются вариантами разработки. Вариант имеет имя, автора и дату.
- Перед отправкой на согласование выбирают один вариант, остальные остаются как «отклонённые» в истории.
- В состоянии «Согласование» могут существовать версии по разным предварительным извещениям. Предупреждение при пересечении объектов в разных извещениях.

### 4.4 Параллельная работа с данными

- Для атрибутов, состава и текстовых полей используется оптимистичная блокировка: при сохранении проверяется номер ревизии записи. При конфликте показываются различия и предлагается выбор, сохранить своё или принять чужое.
- Для файлов САПР автоматического слияния нет. Одновременная правка запрещена блокировкой.
- Для состава допустимо поэлементное слияние: изменения в разных позициях не конфликтуют.
- Если объект входит в несколько извещений в состоянии «Разработка», при проведении второго извещения оно «перебазируется»: система сравнивает его с новой действующей версией и показывает разработчику, что поменялось.

### 4.5 Требования

| № | Требование |
|---|---|
| VER-01 | Нумерация версий основных и временных, неизменяемость утверждённых. |
| VER-02 | «Взять в работу», «Сохранить и вернуть», «Отменить взятие», принудительное снятие администратором с журналом. |
| VER-03 | Просмотр заблокированного объекта другими пользователями без права правки. |
| VER-04 | Блокировка на время согласования, разблокировка при возврате на доработку. |
| VER-05 | Варианты версии в «Проектировании», выбор одного перед согласованием. |
| VER-06 | Оптимистичная блокировка по ревизии записи с показом различий при конфликте. |
| VER-07 | Поэлементное слияние состава, запрет слияния файлов САПР. |
| VER-08 | Перебазирование извещения при проведении другого извещения по тем же объектам. |

## 5. Справочник типов документов компонента

Справочник редактирует администратор. Ниже набор по умолчанию. Коды в скобках ориентировочные, нужно сверить с ГОСТ и принятыми на предприятии обозначениями (Допущение).

| Группа | Тип документа | Для чего | Применим к |
|---|---|---|---|
| Основные | Спецификация (СП) | Состав сборочной единицы | сборочной единице |
| Основные | 3D-модель | Электронная модель | детали, сборочной единице |
| Основные | Чертёж детали (ЧД) | Чертёж | детали |
| Основные | Сборочный чертёж (СБ) | Чертёж | сборочной единице |
| Основные | Габаритный, монтажный, схемы и др. чертежи (ГЧ, МЧ, схемы) | Прочая КД | сборочной единице |
| Сопроводительные | Ведомость спецификаций, покупных изделий, ссылочных и прочих документов (ВС, ВП, ВД и др.) | Ведомости к комплекту КД | сборочной единице |
| Сопроводительные | Технические условия, программа и методика испытаний (ТУ, ПМ) | Нормативная и испытательная документация | сборочной единице |
| Сопроводительные | Расчёты, технические описания, пояснительные записки (РР, ТО, ПЗ) | Обоснование | любому |
| Эксплуатационные | Руководство по эксплуатации (РЭ) | Ввод в эксплуатацию, использование | сборочной единице |
| Эксплуатационные | Паспорт, формуляр (ПС, ФО) | Учёт, гарантии, сведения об изделии | сборочной единице |
| Эксплуатационные | Этикетка (ЭТ) | Маркировка, краткие сведения | сборочной единице, детали |
| Эксплуатационные | Каталог деталей и сборочных единиц, ЗИП, ведомость ЗИП (ЗИ, ВЗИ) | Запасные части | сборочной единице |
| Эксплуатационные | Ремонтные и монтажные документы (РК, ИМ и др.) | Ремонт, монтаж, пуск | сборочной единице |
| Эксплуатационные | Ведомость эксплуатационных документов (ВЭ) | Перечень эксплуатационных документов | сборочной единице |
| Технологические | Маршрутная карта (МК), техпроцесс (ТП), операционные карты | Технология изготовления | детали, сборочной единице |
| Программные | Документы по ГОСТ 19 (описание, руководство оператора и др.) | Для изделий с программой | сборочной единице |
| Прочие | Текстовый документ (произвольный) | Любой другой документ | любому |

Для каждого типа хранятся: группа, применимость, обязательность по стадии, допустимые форматы, правило взаимосвязи (раздел 6), значок и порядок в дереве.

Эксплуатационная документация собирается в группе «Эксплуатационная документация» внутри сборочной единицы и версионируется так же. В электронном виде эксплуатационная документация и её состав описываются по ГОСТ Р 2.621-2024 (формат данных). Нужно решить, поддерживается ли выгрузка в этом формате на первом этапе (открытый вопрос).

Порядок в дереве компонента: у сборочной единицы спецификация, 3D-модель, сборочный чертёж, затем вложенные компоненты и остальные документы по группам. У детали 3D-модель, чертёж детали, затем остальные.

## 6. Правила взаимосвязи по умолчанию

- Изменение спецификации или 3D-модели сборочной единицы ведёт к новой версии компонента и требует проверки зависимых документов.
- Изменение состава (спецификации) требует проверки ведомости покупных изделий, ведомости эксплуатационных документов, ЗИП, РЭ и каталога деталей («рекомендуется пересмотреть»).
- Изменение 3D-модели и чертежа детали влечёт проверку МК и техпроцесса детали.
- Изменение эксплуатационных документов не требует новой версии компонента, если сам компонент не менялся. Версия только у документа.
- Каждое правило имеет уровень: «обязательно» (блокирует), «предупреждение» (разработчик подтверждает), «справочно».

| DOC-02 | Прикрепление сопроводительных и эксплуатационных документов (файл или ссылка) с тем же версионированием и изменением по ИИ. |

## 7. Контрольные рубежи (простые проекты)

Для организации разработки новых изделий допускается объект «Контрольный рубеж»: обозначение с префиксом проекта и нумератором, наименование, описание, дата. Базовый перечень задаёт предприятие (ТЗ, эскизный проект, опытный образец, этапы). Состояния: «Черновик» при создании, «Утверждён» проставляет руководитель проекта. Реализуется на этапе 3.

## 8. Производственные составы (mBOM) и инженерные составы (eBOM)

Статус: предложение, ждёт подтверждения заказчика (вопрос V-12 части 10).

### 8.1 Проблема

В вашей системе производственная спецификация заказа хранится в тех же таблицах и показывается в том же модуле PDM, что и инженерные составы. Конструкторы путают их, а у заказа с составом из архива нет проверки, насколько он совпадает с инженерным.

### 8.2 Два вида составов

| | Инженерный состав (eBOM) | Производственный состав (mBOM) |
|---|---|---|
| Что это | Состав изделия по конструкторской документации | Состав под конкретный заказ или партию |
| Кто ведёт | Конструктор, технолог | ПДО, технолог по заказу |
| Где хранится | Модуль PDM: «В работе» и «Архив» | Раздел «Производственные составы» и карточка заказа, **не в реестре PDM** |
| Версии | Версии узлов, архив неизменяем | Ревизии заказа (часть 04, раздел 12), версий узлов нет |
| Что можно менять | Всё по правилам изменений | Количество, замены, дополнительные позиции. Всё остальное только через eBOM |
| Состояния | Жизненный цикл версии | Этапы подготовки заказа: конструктор, технолог, проверка, «Готово» |

Хранить можно в тех же таблицах (разделять признаком вида), но показывать и права различать обязательно.

### 8.3 Идентичность составов

Mбом всегда **порождается** из версии eBOM и хранит: ссылку на версию-источник, хеш состава источника на момент создания, список допустимых отличий (дополнительные позиции, замены, изменённое количество). Система показывает рядом с составом заказа индикатор:

| Индикатор | Смысл |
|---|---|
| Совпадает | Состав равен eBOM, хеши равны, отличий нет |
| Допустимые отличия | Есть только явно помеченные отличия (дополнительные позиции, замены, количество). Показывается их список |
| Расходится | После создания eBOM изменился (появилась новая версия), или состав правили вручную мимо допустимых отличий |

Решение принимает ПДО (часть 04, раздел 12). Сравнение использует тот же хеш состава узла, что и версии (в вашей системе он уже есть).

### 8.4 Требования

| № | Требование |
|---|---|
| MBOM-01 | Производственный состав отдельный вид объекта, не показывается в реестре PDM, имеет свои значок, название этапов и права. |
| MBOM-02 | Состав порождается из версии eBOM и хранит ссылку на источник и его хеш. |
