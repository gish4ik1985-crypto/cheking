# 10. План исправлений и открытые вопросы

Основа: часть 09 (сравнение с `erp-yarst`). Здесь для каждой проблемы указано, что менять в коде вашей системы, как это сделать в рамках правил репозитория, чем рискуем, и что нужно решить заранее. Код не менялся, это план.

## 1. Правила репозитория, которым подчиняются все исправления

Из `CLAUDE.md` и `docs/00_rules/`:

- Бизнес-логика только в `app/Service/<Модуль>/`, контроллер вызывает сервис, валидация только через Form Request.
- Логика не живёт в базе: триггеры, функции и представления с бизнес-логикой запрещены. В базе допустимы только ограничения целостности, индексы, значения по умолчанию.
- Новая колонка обосновывается до миграции: зачем, кто пишет, кто читает, что у старых строк, почему не влезло в существующее. Деструктивные миграции только с явным «да» и дампом.
- Vue только на Options API, страницы подключаются лениво, выпадающие списки через `UniversalSelector`.
- Тесты: только `DatabaseTransactions`, один тест-файл на сервис, комплексные сценарии вместо россыпи.
- Документация пишется только после приёмки задачи и переписыванием, не дописками.
- Ветки: от `dev`, имя по ключу задачи, слияние только по явной команде.

Следствие: наши требования `VER-xx`, `DOC-xx`, `APR-xx` превращаются в задачи по этим правилам, а не в отдельный проект.

## 3. План по проблемам из части 09

### P-06. Нет блокировки при редактировании (P1)

- **Что добавить:** таблицу блокировок (`document_locks`: объект, владелец, время взятия, срок, причина) и номер ревизии записи (`row_version`) для оптимистичной блокировки.

## 4. Что можно переиспользовать из нашего проекта

Это разработки проекта `Checking`, которые могут встать в вашу систему как отдельный сервис или библиотека.

| Что | Как использовать |
|---|---|
| Движок правил проверки чертежей (`checking/engine.py`) | Вызывается как сервис, возвращает замечания с кодом, уровнем и текстом. Подходит как «нормоконтроль» перед согласованием заявки. Нужен интерфейс (REST или очередь заданий) |
| Коды и тексты замечаний | Остаются неизменными (обратная совместимость), заносятся в справочник на стороне ERP для отображения |
| Сверка с Excel и комплектность | Уже совпадает с вашими проверками НСИ и технологий. Использовать как второй источник |
| Пиктограммы (часть 08) | Дополняют `ProductIcon` и `NodeTypeIcon`, хранятся как SVG, значки берутся из справочника типов |
| Схема процесса изменений (часть 04) | Основа для обновления документации модуля «Изменения» |
