# 07. Нефункциональные требования, приёмка, этапы

В методологии нефункциональные требования (производительность, резервирование, интерфейс) не описаны. Значения ниже предложены нами и все помечены как Допущение, их нужно подтвердить после изучения текущей системы.

## 1. Нефункциональные требования

| № | Требование | Значение (Допущение) |
|---|---|---|
| NFR-01 | Число одновременных пользователей | 50, запас до 200 |
| NFR-02 | Объём данных | до 100 тыс. компонентов, 1 млн версий документов |

## 2. Критерии приёмки

Критерии по изменениям и версиям собраны в частях 02 и 04. Общие критерии:

1. Нельзя сохранить правку в утверждённой версии, система предлагает создать новую.
2. После проведения ИИ прежняя версия «Заменён по ИИ» с датой, новая действует, просмотр по прошлой дате показывает прежнюю.
3. Критическое замечание автопроверки блокирует отправку на согласование.
4. Два пользователя не могут одновременно править один файл: второй видит владельца блокировки и может смотреть.
5. Два пользователя могут одновременно править разные атрибуты одного компонента без потери данных, конфликт одного поля показывается с различиями.
6. Утверждение версии без обязательного вторичного представления невозможно.
7. К сборочной единице можно прикрепить РЭ, ПС, ФО, ведомости и прочие документы из справочника, они получают версии и меняются только через ИИ.
8. Для сборочной единицы с отсутствующим обязательным документом отображается замечание о комплектности.
9. Права на смену состояния проверяются по правилу перехода и роли.
10. Миграция загружает существующие документы с отчётом по несопоставленным, прежние замечания совпадают по кодам и текстам.

|---|---|---|
| 1 | Компоненты, документы, версии и состояния, справочник типов, состав и связи, взятие в работу, хранилище файлов, просмотр PDF, ИИ с правилами взаимосвязи, анализ влияния на родителей, автопроверка, шаблоны согласования, ЭП и бумажный лист, права, журнал, пиктограммы | Решения по хранению файлов и каталогу пользователей |
| 2 | ПИ и ПР, комплектность, ведомости, просмотр 3D, интеграция с КОМПАС, поиск и отчёты, печатные формы, уведомления, миграция | Готовый перенос 3D, конвертер |
| 3 | ДИ и ДПИ, рассылка абонентам, исполнения и вариантные правила, контрольные рубежи, выгрузка эксплуатационной документации по ГОСТ Р 2.621-2024, интеграция с ERP и MES | Этап 2 |
