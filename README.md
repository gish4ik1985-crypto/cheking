# Проверка чертежей

Локальная программа (Python + веб-интерфейс) для автоматической проверки конструкторских чертежей по правилам ЕСКД.
Работает без интернета и облачного ИИ: только правила и таблицы стандартов. Распознавание сканов (OCR) тоже локальное.

## Запуск

```bat
run.bat
```

При первом запуске создаётся окружение `.venv` и ставятся зависимости, затем открывается браузер
`http://127.0.0.1:8765`. Перетащите чертежи (или папку, или ZIP), при желании добавьте спецификацию и нажмите **Проверить**.

Из командной строки:

```bat
check.bat "D:\КД\Опора пассивная" --spec "СП Опора пассивная.xls" --out отчёт.xlsx
```

## Что читается

| Формат | Как |
|---|---|
| PDF из КОМПАС / Solid Edge (векторный) | текст и координаты, символы шрифтов КОМПАС (⌀, °, ×) перекодируются |
| PDF-скан, PNG/JPG/TIF | локальный OCR (RapidOCR, модель для кириллицы), ~3–10 с на лист |
| КОМПАС `.cdw` без КОМПАСа | основная надпись (обозначение, наименование, материал, масса, подписи) и ТТ из файла; размеров нет |
| КОМПАС `.cdw` при установленном КОМПАС-3D | конвертация в PDF через API → полная проверка |
| Solid Edge `.dft` при установленном Solid Edge | конвертация в PDF через API → полная проверка; без Solid Edge — только свойства файла |
| PDF-пакет с несколькими документами | делится по основным надписям формы 1, каждый документ проверяется отдельно |
| DXF-развёртки (`.dxf`) | для сверки с чертежом листовой детали: габарит, отверстия, толщина из имени файла |

Особенности, учтённые по реальным файлам: листы Solid Edge А3/А2 с поворотом страницы, символьные шрифты
КОМПАС (Symbol_A) и Solid Edge (SolidEdgeANSI1Symbols: «O» → ⌀, «v» → °), основная надпись Solid Edge
с графами «Рев./Вер.», шероховатость по старой редакции ГОСТ 2.309 (значение без «Ra» над знаком √),
таблицы параметров зубчатых колёс (числа в ячейках — не размеры), дубли текста в PDF.

Спецификация/ERP: шаблон СП ERP ЯСТ (`.xlsx/.xlsm`), табличный экспорт ERP, отчёт спецификации КОМПАС (`.xls`).
Позиция ищется по обозначению, затем по артикулу (`100-000032 ЮМЛТ.484289.002 Люк.pdf`).
Можно подключить базу ERP напрямую (только чтение) — см. `config.json → erp_db`.

## Что проверяется

**Размеры, допуски и посадки** (ГОСТ 25346-2013, ГОСТ 25347-2013 / ISO 286, ГОСТ 2.307-2011)

| Код | Проверка |
|---|---|
| D01 | поле допуска существует (буква, квалитет IT1…IT18, регистр отверстие/вал), установлено для данного размера |
| D02 | поле входит в ряды ГОСТ 25347 |
| D03 | отклонения в скобках совпадают с полем (`⌀20H7(+0,025)` → должно быть +0,021) — расчёт по таблицам ISO 286 |
| D04 | верхнее отклонение больше нижнего |
| D05 | равные отклонения записаны через ± |
| D06 | одинаковое число знаков в отклонениях |
| D07 | десятичная запятая |
| D08 | у справочных размеров (*) нет отклонений |
| D09 | знаки * и ** пояснены в ТТ |
| D10 | неуказанные предельные отклонения оговорены в ТТ (ГОСТ 30893.1, H14/h14/±IT14/2, ГОСТ 23118, ОСТ4 ГО.070.014 — список в config.json) |
| D11 | номинал посадочного размера из ряда Ra40 ГОСТ 6636 |
| D12, D13, D18 | посадка: отверстие/вал не перепутаны, система H/h, рекомендуемая ли, расчёт зазоров/натягов |
| D14 | шероховатость соответствует квалитету (IT7 → Ra ≤ 1,6 …) |
| D15 | метрическая резьба: диаметр и шаг по ГОСТ 8724, поле допуска по ГОСТ 16093 |
| D16 | русские буквы в обозначениях допусков (Н7 вместо H7) |
| D17 | фаски и малые радиусы по ГОСТ 10948 |

**Технологичность**

| Код | Проверка |
|---|---|
| T01 | отверстие на листовой детали меньше толщины листа (лазер) |
| T02 | очень жёсткие допуски (IT5 и точнее) |
| T03 | на листовой детали допуски точнее IT11 — лазер/плазма не обеспечит, нужна мехобработка |
| T04 | мало витков резьбы в тонком листе |

**Расположение размеров** (`checking/layout.py`, ГОСТ 2.307-2011): D31 — надписи (размеры, текст) наложены друг на
друга; D32 — размерная линия ближе 10 мм к контуру (оценка по длине выносных линий, замечание только при явном
нарушении, ≲8 мм); D33 — параллельные размерные линии ближе 7 мм. Размеры без выносных линий (на самом изображении,
на полках) не проверяются.

**Основная надпись и масса** — только то, где реально ошибаются:
масса против спецификации/3D (B02), масса физически возможна по габаритам и плотности (B03),
масса не указана (B01), материал без сортамента / толщина не совпадает (B07),
обозначение в штампе = имя файла = графа 26 (B04), формат (B05), масштаб (B06), номер изменения в имени файла (B08).

**Масса сборок** (`checking/masscheck.py`):

* B15 — масса не больше массы сплошного стального бруса по габаритам изображения. Габариты — наибольшее связное
  изображение на поле листа (линии и дуги ближе 4 мм), умноженное на масштаб (крупнейший из штампа и надписей видов;
  если размеры больше изображения — растягивается до них). Оценка заведомо сверху (с выносками и размерами),
  поэтому ловит только невозможное: граммы вместо килограммов, лишние разряды, массу чужой модели. Для сборок и
  для деталей, у которых B03 не посчитана (нет материала или габаритов).
* Сверка документов одной проверки между собой (все файлы и все листы пакета PDF):
  A15 — масса сборки не меньше суммы известных масс составных частей (ошибка), A13 — равна сумме, когда массы
  всех частей известны (±5 %), A16 — масса в графе «Примечание» спецификации совпадает с массой в чертеже
  составной части, A17 — наименование в спецификации по основной надписи чертежа составной части; одно
  обозначение в разных спецификациях — одно изделие.
  Масса составной части берётся из её чертежа в этой же проверке, затем из загруженной СП, затем из графы
  «Примечание» («0,03 кг»; материалы «1 | кг»). В отчёте у сборки — строка «Масса частей»: сколько позиций
  с известной массой и их сумма.

**Сверка с ERP/спецификацией** — наименование (E02), марка, сортамент, толщина листа/диаметр круга (E04), длина заготовки (E05).

**Сверка с DXF** (положите DXF рядом с PDF или в тот же ZIP; сопоставление по артикулу, обозначению или имени):
X01 габарит развёртки есть среди размеров чертежа, X02 каждое отверстие чертежа есть в DXF в нужном количестве
(резьбовые — по диаметру под резьбу), X03 в DXF нет лишних отверстий, X04 толщина из имени DXF («_5мм») = лист на чертеже.
Слои гравировки/маркировки (Up_Etch, текстовые) и осевые не учитываются, окружности из дуг собираются.

**Сварка** (ГОСТ 2.312): W01 указан катет после ⊿, W02 код соединения есть в указанном стандарте
(ГОСТ 5264, 14771, 8713, 11534, 11533, 23518, 14776, 14098), W03 стандарт указан в обозначении или ТТ,
W05 стандарт в обозначении не противоречит ТТ, W04 катет не больше 1,2·s.

**Остальные конструкторские ГОСТы** (полный перечень с кодами — в «Настройках», `/admin`)

| Группа | Стандарты | Что проверяется |
|---|---|---|
| Общие допуски | ГОСТ 30893.1/.2 | «±IT14/2» со знаком ±, классы f/m/c/v и H/K/L латиницей (P04–P06) |
| Нормальные ряды | ГОСТ 6636, 10948, 8908 | номиналы посадок, фаски и радиусы, нормальные углы (D11, D17, D23) |
| Резьбы | ГОСТ 8724, 16093, 24738, 6357 | метрическая (в т.ч. «М6-7Н» кириллицей), трапецеидальная Tr, трубная G (D15, D24, D25) |
| Допуски формы и расположения | ГОСТ 2.308, 24643 | база из рамки обозначена знаком базы (а не буквой разреза), ряд значений, база у соосности/биения (G01–G04) |
| Шероховатость | ГОСТ 2.309, 2789 | ряд Ra/Rz, знак (√) только при местных обозначениях (R01–R03) |
| Изображения и буквы | ГОСТ 2.305, 2.316 п. 4.17–4.18, 2.302 | запрещённые буквы, повторы, обозначение секущей плоскости, слова «Вид/Разрез», масштаб надписи (V01–V07) |
| ТТ и текст | ГОСТ 2.316, 2.105 | сквозная нумерация пунктов, десятичная запятая, знаки без чисел (P01–P03) |
| Ссылки на стандарты | ГОСТ 2.105 | заменённые редакции (список редактируется), «по ГОСТ» без номера (N01, N02) |
| Термообработка, покрытия | ГОСТ 2.310, 9.306 | пределы твёрдости, глубина слоя, «Ц6.хр» (H01–H06) |
| Материал | ГОСТ 2.109 + стандарты на сортамент и марки | вид сортамента, стандарт на марку/сортамент (M01–M03) |
| Зубчатые колёса, шлицы | ГОСТ 2.403, 9563, 1643, 1139, 6033 | таблица параметров, модуль, d = m·z/cos β, «8-С ГОСТ 1643-81», шлицы (Z01–Z06, K03, K04) |
| Элементы деталей | ГОСТ 14034, 23360, 11284 | центровые отверстия, шпоночные пазы; отверстия под крепёж в T01 (K01, K02) |
| Сборочные чертежи | ГОСТ 2.109 разд. 3, ГОСТ 2.106 | габаритные размеры, номера позиций ↔ спецификация, шрифт номеров, повторы; спецификация на поле чертежа: только А4 и по форме 1, порядок позиций (резерв номеров допустим), количество, разделы, повтор обозначений; масса сборки и составных частей (A01–A17) |

**Спецификация по ГОСТ 2.106** (группа S в настройках). Загруженная СП — шаблон ERP, отчёт КОМПАС «Report»,
экспорт из Solid Edge — разбирается по номерам позиций «1.2.3» на спецификации отдельных сборочных единиц, и каждая
проверяется как документ по форме 1. В отчёте СП — отдельный документ с составом по сборкам.

| Код | Проверка |
|---|---|
| S01 | разделы в порядке ГОСТ 2.106 (документация, комплексы, сборочные единицы, детали, стандартные, прочие, материалы, комплекты) |
| S02 | одна составная часть — одной строкой с общим количеством (а не 12 строк «Гайка … 1 шт.») |
| S03–S05 | сортировка: сборочные единицы и детали — по возрастанию обозначений; стандартные — по алфавиту, затем по стандарту; прочие — по алфавиту |
| S06, S07 | у деталей и сборочных единиц — обозначение документа (не артикул); у стандартных/прочих/материалов графу не заполняют |
| S08 | стандартные изделия — с обозначением стандарта |
| S09–S11, S14 | количество; единицы у материалов; детали БЧ — с материалом и размерами; наименование |
| S12, S13 | масса сборки = сумма масс составных частей (материалы-расходники не учитываются); позиции по порядку |

Разделы определяются по графе «Раздел» (КОМПАС) или по группе артикула (1xx сборочные единицы, 2xx детали,
3xx стандартные, 4xx прочие, 5xx материалы). Те же правила применяются к спецификации на поле чертежа. Номера позиций
на сборочном чертеже сверяются с загруженной СП (по обозначению сборки).

Таблицы на поле чертежа (спецификация КОМПАС, таблица составных частей Solid Edge, таблица исполнений группового
чертежа) распознаются по сетке линий и заголовку «Обозначение» и в ТТ/размеры не попадают. Номера позиций —
целые числа на полках выносок, крупнее размерного шрифта.

**Комплектность по спецификации** — для каждой детали и сборки из СП: есть ли чертёж, есть ли в нём ошибки;
чертежи, которых нет в СП. Стандартные/прочие изделия, материалы, покупные (артикулы 3xx–5xx) и позиции
«Без чертежа» не требуют чертежа.

## В отчёте

* лист с пронумерованными рамками на местах замечаний, вкладки «Размеры», «Допуски», «Основная надпись», «ТТ»;
* **«не ошибка»** у каждого замечания — скрыть для этого чертежа или отключить правило везде (хранится в
  `exceptions.json`, применяется ко всем следующим проверкам; скрытое можно вернуть);
* **Excel** (сводка, комплектность, замечания, размеры, ТТ) и **перечень замечаний в Word** для конструктора —
  на весь пакет или на один документ, с графой «Отметка об устранении» и подписями.

## API для ERP

`POST /api/v1/check` (multipart): `file` — чертёж, `dxf` — развёртка (необязательно), поля карточки изделия
`designation, sku, name, mass, material, grade, base_size, blank_size, dxf_length, dxf_width`. Ответ —
`{"success": true, "drawings": [...]}` с замечаниями. `GET /api/v1/health` — проверка связи. Токен:
переменная `CHECKING_API_TOKEN` → заголовок `X-Api-Token`. Для сервера — `Dockerfile` (порт 8765).

## Настройки (администратор)

Кнопка **«Настройки»** (`/admin`):

* **Проверки по ГОСТ** — все 130 проверок **списком**: переключатель вкл/выкл, код, описание, группа и стандарт,
  важность (ошибка / предупреждение / замечание). Фильтры «включённые / выключенные / изменённые», по группе,
  поиск, «Включить/Выключить показанные», «По умолчанию». Вид «По ГОСТам» — те же проверки по 21 группе
  с галочкой на всю группу. Каждая строка — одна проверка (совмещённые раньше коды разделены).
  Настройки сразу действуют на все отчёты, в том числе уже сохранённые. Ссылка «отключить правило» в отчёте
  выключает проверку здесь же.
* **Свои правила** — правила предприятия без программирования (коды U01, U02…), форма с типом проверки:
  «в тексте должно быть / не должно быть» (ТТ, весь текст, основная надпись; текст или регулярное выражение),
  «графа основной надписи» (заполнена / равна / содержит / шаблон), «ограничительный перечень» и «запрещённые
  значения» (марки материалов, фрагменты записи материала, поля допусков, метрические резьбы, стандарты, Ra),
  «предел» (квалитет не точнее IT…, Ra не точнее…, толщина листа / масса не больше…). Для каждого — к каким документам
  применять (детали, сборки, листовые, спецификации; фильтр по материалу и началу обозначения), важность, свой текст
  замечания (`{value}` — найденное значение) и ссылка на документ (СТП). Кнопка «Проверить на отчёте» показывает, что
  правило найдёт в сохранённом отчёте; готовые примеры — в списке «Начать с примера…». Правила попадают в общий список
  (группа «Правила предприятия») и сразу действуют на все отчёты, включая сохранённые.
* **Параметры** — допуск массы, порог отверстия на листе (k·s), квалитеты, витки резьбы, диапазон твёрдости, OCR.
* **Справочники** — коды организаций, ссылки на общие допуски, таблица заменённых редакций стандартов.
* **Исключения** — замечания, отмеченные «не ошибка».
* **Доступ** — пароль администратора (хранится хэш в `admin.json`). Пока пароль не задан, настройки открыты всем.

Всё хранится в `config.json` (раздел `"rules"` — только отличия от настроек по умолчанию) и там же — подключение
к базе ERP.

## Проверено на реальных чертежах

* 7 чертежей «Опоры пассивной» (КОМПАС) + спецификация: найдено расхождение массы «Фиксатора» (0,05 против 0,118 кг);
* 18 чертежей редуктора (Solid Edge): перепутанные отклонения (30, ⌀28,5, ⌀100), нулевой допуск ⌀168,
  округлённые отклонения полей H7/H8/JS7/h9, Ra 6,3 на посадке h6 под игольчатый подшипник, пропущенные материал и масса,
  масштаб «0,2:1»; все ошибки подтверждены по изображениям листов;
* пакет «ОН-0020 СБ» (КОМПАС): неполное обозначение шва «У5-⊿» без катета;
* по остальным ГОСТам (редуктор): «Отв. центр С4» (у формы C нет d = 4), рамки допусков венца 280-000060
  ссылаются на базу «Г», которая обозначает разрез Г-Г (обозначена только база Д), ГОСТ 13755-81 вместо
  13755-2015, «8-С» без ГОСТ 1643-81, «ГОСТ6333-80»/«ГОСТ6033-88» вместо ГОСТ 6033-80, «IT14/2» без «±»,
  «130 ГОСТ 2590» без «Круг»; «Ц6хр» вместо «Ц6.хр» на «Кольце» (КОМПАС).

## Ограничения

* Размеры извлекаются из текста PDF; привязка размера к конкретной поверхности не определяется
  (поэтому проверка «шероховатость ↔ квалитет» сделана по чертежу в целом).
* Знаки сварных швов, выполненные только графикой (без текста), не распознаются — проверяются текстовые обозначения и ТТ.
* Конвертация `.cdw`/`.dft` через КОМПАС-3D / Solid Edge и прямое подключение к базе ERP
  на этом компьютере не проверены (САПР не установлены, база недоступна).
* Габариты для проверки массы оцениваются по наибольшим размерам; на сложных деталях — только предупреждение.

## Переносимая версия (exe)

`build_exe.bat` собирает папку `dist\ПроверкаЧертежей\` (≈350 МБ, Python внутри). Её целиком копируют на любой
компьютер с Windows 10/11 — ничего ставить не нужно; запуск — `ПроверкаЧертежей.exe`, откроется браузер.
Настройки (`config.json`, `admin.json`, `exceptions.json`) и отчёты (`work`) создаются рядом с exe; при обновлении
программы эти файлы и папку сохраняют. Остановить — закрыть окно консоли. Для конвертации `.cdw`/`.dft`
по-прежнему нужны КОМПАС-3D / Solid Edge на этом компьютере.
